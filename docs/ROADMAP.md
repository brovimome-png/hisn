# خطة الطريق — حِصن

> الحالة: **مقترح للمراجعة** (المرحلة 0). لا مرحلة مُنفَّذة بعد.
> قاعدة ثابتة: **الوثائق لا تعد بشيء لم يثبته اختبار.** أي بند لم يُجرَّب يُكتب بجانبه «لم يُختبر».

## كيف تُقرأ المراحل

- كل مرحلة = **Issue واحدة** على GitHub، ولها فرعها وPull Requests صغيرة (تغيير واحد لكل PR).
- «شرط النجاح» = اختبارات مسمّاة يجب أن تمرّ في CI قبل إغلاق المرحلة. لا يُغلق Issue بكلام.
- «خارج المرحلة» = ما لا يُبنى فيها ولو كان سهلًا، حتى لا تتضخّم.
- أي تغيير في محتوى مرحلة = تعديل هذا الملف في PR + إشعارك قبل التنفيذ.

## المرحلة 0 — التأسيس (التي نحن فيها)

**المحتوى:** README، PRD، ARCHITECTURE، ورقات ADR، ROADMAP، AGENTS، CI أولي.
**شرط النجاح:**
- [ ] CI يمرّ على PR التأسيس (فحص روابط الوثائق) — *لم يُختبر بعد*.
- [ ] لا ملفات كود مصدري (`*.kt`, `*.java`) في المستودع.
- [ ] موافقتك على القرارات المعلَّمة «بانتظار الموافقة».
**خارج المرحلة:** أي مشروع Gradle، أي شاشة، أي كود.

## المرحلة 1 — الهيكل والبناء

**المحتوى:** مشروع Gradle متعدد الوحدات (`app`, `vpn`, `core:filter`, `core:dns`, `data`, `updater`)،
تطبيق فارغ يعمل، تعريب أولي (عربي/إنجليزي)، تفعيل وظيفة CI لبناء أندرويد.
**شرط النجاح:**
- [ ] `./gradlew assembleDebug testDebugUnitTest lint` ينجح محليًا وعلى CI (ubuntu-latest).
- [ ] يظهر فحص Gradle Wrapper validation ناجحًا في CI.
- [ ] `FilterEngineSmokeTest` و`DnsPacketRoundTripTest` (اختبارات هيكلية بسيطة) تمرّ.
- [ ] التطبيق يُثبَّت ويفتح شاشة واحدة بالعربية — يُتحقَّق يدويًا ويُذكر الجهاز ونظامه في PR.
**خارج المرحلة:** أي حجب فعلي، أي خدمة VPN، أي قائمة تصفية.

---

## المرحلة 2 — نواة الحجب (MVP)

**المحتوى:** خدمة VPN محلية، لقطة DNS، محرك مطابقة نطاقات بقائمة hosts مضمّنة، تشغيل/إيقاف،
إشعار دائم، ميزانية أداء أولية.
**شرط النجاح:**
- [ ] اختبارات وحدة على JVM: `HostsParserTest` (أسطر معلّقة، مسافات، نطاقات خاطئة، ملف ضخم)،
      `DomainMatcherTest` (مطابقة دقيقة، نطاق فرعي، عدم مطابقة لاحقة خاطئة مثل `notexample.com`).
- [ ] `DnsParserFuzzTest` لا ينهار على حزم مشوّهة (حد أدنى 10k مدخل عشوائي).
- [ ] اختبار على جهاز/محاكي: بدء الخدمة يفتح واجهة VPN، إيقافها يغلقها، والنظام يعرض مفتاح VPN.
- [ ] قياس يدوي موثّق: استهلاك البطارية في ساعة استخدام عادي، والأرقام تُكتب في PR (يهدي الهدف الرقمي).
- [ ] التحقق العملي: نطاق إعلاني معروف محجوب، ونطاق محتوى معروف يعمل. **يُذكر الجهاز/الإصدار.**
**خارج المرحلة:** تحديث القوائم من الشبكة، الاستثناءات لكل تطبيق، الإحصاءات، يوتيوب.

## المرحلة 3 — إدارة القوائم

**المحتوى:** دعم صيغ القوائم (hosts + مجموعة فرعية محدّدة من Adblock Plus)، تنزيل آمن، تحقّق
سلامة، كتابة ذرّية، نسخة رجوع، قوائم مخصّصة، تحرير قائمة ضمن التطبيق.
**شرط النجاح:**
- [ ] `FilterListParserTest` يغطي: قواعد `||domain^`، `@@` استثناءات، تعليقات، قواعد غير مدعومة
      (تُتجاهَل بأمان وتُسجَّل عدّادًا)، وملفات بترميز UTF-8 مع BOM.
- [ ] `UpdaterTest`: ملف ضخم يُرفض، استجابة ليست نصًا تُرفض، انقطاع في منتصف التنزيل يبقي النسخة
      القديمة عاملة، بصمة غير مطابقة تُرفض.
- [ ] `AtomicSwapTest`: لا تبقى ملفات مؤقتة متروكة بعد فشل متعمّد.
- [ ] تحديث قائمة حقيقية على جهاز، مع إثبات أن الحجب استمر دون إعادة تشغيل التطبيق.
**خارج المرحلة:** قوائم المانعين الآخرين المنسوخة، أي اشتراك مدفوع، أي سيرفر لنا.

## المرحلة 4 — التحكّم لكل تطبيق والإحصاءات المحلية

**المحتوى:** استثناء/تضمين تطبيقات (عبر `addAllowedApplication` وأخواتها)، إحصاءات محلية
مصنَّفة، وضع «بلا سجلات»، شاشة حدود الحجب.
**شرط النجاح:**
- [ ] `PerAppRulesTest`: تطبيق مستثنى لا يُحجب له شيء، والباقي يعمل كالسابق.
- [ ] `StatsAggregatorTest`: العدّاد يزيد مرة واحدة لكل قرار، ويتوقف كليًا في وضع بلا سجلات.
- [ ] اختبار جهاز: تفعيل الاستثناء لتطبيق معيّن يظهر أثره فعليًا (نطاق تجريبي).
- [ ] لا يظهر في تحليل الشبكة أي طلب خارجي جديد بسبب الإحصاءات (تحقّق موثّق).
**خارج المرحلة:** أي مزامنة سحابية للإحصاءات، أي مقارنة مع مستخدمين آخرين.

---

## المرحلة 5 — منع التتبّع المتقدّم

**المحتوى:** تصنيف المتعقّبات، كشف CNAME cloaking (يتطلّب استعلامًا إضافيًا)، دعم DNS مشفّر
كخادم أعلى (DoH) كخيار، سياسة تحديث القوائم الافتراضية.
**شرط النجاح:**
- [ ] `CnameUncloakTest`: نطاق يتنكّر عبر CNAME يُصنَّف متعقّبًا دون كسر المحتوى.
- [ ] `DohUpstreamTest` (بخادم وهمي محلي): فشل DoH يعود تلقائيًا إلى DNS العادي دون تجميد الشبكة.
- [ ] قياس أثر الأداء موثّق ومقارَن بالمرحلة 2.
**خارج المرحلة:** فك تشفير HTTPS، تصفية على مستوى المسار (URL) عبر MITM.

## المرحلة 6 — المتصفحات ويوتيوب (بحث وتوثيق الحد)

**المحتوى:** التحقق العملي من حجب إعلانات صفحات الويب في Chrome وبقية المتصفحات، ومعالجة
تعارض «DNS الآمن» في المتصفح، ودراسة (spike) موثّقة لخيارات يوتيوب.
**شرط النجاح:**
- [ ] تقرير موثّق: المتصفحات المُختبَرة، إصداراتها، وما حُجب فعليًا وما لم يُحجب.
- [ ] اختبار/إجراء موثّق لحالة تفعيل المتصفح لـ«DNS الآمن» (يُكتشف ويُرشَد المستخدم).
- [ ] نتيجة مكتوبة لقرار يوتيوب: إمّا «غير ممكن داخل التطبيق» مع بديل واضح، وإمّا خطة جديدة
      بموافقتك — **لا تنفيذ ترقيع أو نسخ تطبيقات**.
**خارج المرحلة:** أي حل يتجاوز سياسات جوجل/يوتيوب، أو يتطلّب شهادات MITM.

## المرحلة 7 — الإصدار 1.0

**المحتوى:** اكتمال الإنجليزية، إمكانية الوصول، ملفات F-Droid، بناء إصدارات آليًا من GitHub
(وسم ← بناء ← توقيع ← نشر)، بصمات تحقّق، سياسة خصوصية مكتوبة.
**شرط النجاح:**
- [ ] كل نصوص الواجهة موجودة في `ar` و`en` (فحص CI يقارن المفاتيح ويفشل عند نقص).
- [ ] اختبارات إمكانية الوصول الأساسية تمرّ (أحجام لمس، تسميات لقارئ الشاشة).
- [ ] إصدار تجريبي واحد على الأقل مبنيّ آليًا من GitHub، موقّع، ومُثبَّت على جهاز حقيقي.
- [ ] بناء متكرر (نفس المُدخل ← نفس البصمة) — إن تعذّر، يُكتب ذلك بصراحة في الوثائق.
**خارج المرحلة:** Google Play، أي ميزة سحابية.
